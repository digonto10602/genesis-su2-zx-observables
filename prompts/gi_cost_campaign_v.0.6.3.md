## 0. Why this session exists, and why it is not blocked

Session `c060_p0_20260908_3` delivered a correct diagnosis and stopped, properly, at the mandatory Fable planning/escalation step: weekly Fable usage was 51% against a configured 50% ceiling, so no production physics repair, no C0 re-gate and no C1 amendment could be accepted. This session does work that **requires no physics sign-off**, because it changes no physics: it repairs a documentation-generation *scope* defect and packages existing evidence for review. It is explicitly permitted under the same policy that blocks C0, and it removes a real precondition for the eventual repair.

**The scope defect.** `docs/CODE_FUNCTION_INVENTORY.md` (886 lines, 148 entries, AST-generated by `tools/function_inventory.py`) and `docs/CODE_LOGIC_AND_TESTS.md` (226 lines, Mermaid flow, per-module narrative) cover **`src/su2zx/`, `tools/` and `tests/` only** — the archived, published v0.4.0 research package. They do not cover **`runs/section8_v0.5.0_20260907T0628Z/src/su2qc/`** (23 modules), which is where every module under active gate lives: `twin/twin.py`, `compile/run_g4.py`, `compile/route.py`, `encodings/l12.py`, `conventions.py`, `dynamics/engine.py`, `ham/*`, `circuits/*`. The string `su2qc` appears in `docs/` exactly once, inside a referenced review file.

Consequences, stated plainly because they are the justification for this session:

- `run_counts` — the function carrying the adjacent-seed defect — **has no documented signature, docstring contract or call record** in any generated inventory.
- `channel_weights`, `channel_closure_residual`, `physical_yield` — the three functions behind the P3/P4 specification ambiguities — are undocumented, so no written contract contradicted the code.
- The only Mermaid architecture diagram in the tree describes the v0.4.0 compiler/TN pipeline, **not** the Section-8 twin/gate pipeline that C0 gates.
- Graphify partially compensates — 313 `su2qc` nodes, 43 touching the twin module, out of 2,075 nodes / 2,788 edges / 206 communities at commit `723d083d` — but it ran AST-only, its community labels are recorded stale, and it retained 11 nodes from a file outside the current scan corpus. A callable node labelled `run_counts()` is not a contract.

A defect of exactly this class survives review when the generated documentation and the gated code are different packages. That is the finding this session closes.

**The second deliverable.** The v0.6.2 diagnostic archive is **195 MB** and is not usable for review by a human or an assistant: ~146 MB is three `.qpy` circuit files (54.4 / 36.7 / 19.0 MB) plus their `.qasm` twins (17.7 / 11.9 / 6.1 MB), and a further ~13 MB is the Graphify AST cache. Everything a reviewer actually needs — source, tests, contracts, measured JSON/CSV, figures, logs, manifests — is under 25 MB. This session produces a second, navigable archive built for step-by-step interrogation of code, physics and execution.

**R15 · Write `docs/SU2QC_CONTRACTS.md` — the document whose absence let the defect through.** One entry per public callable in `su2qc`, each stating: inputs, outputs, **invariants the caller may rely on**, side effects, error behaviour on empty/degenerate input, and the test that enforces each invariant (or `UNENFORCED` where none does). The following entries are mandatory and must be written exactly as *currently true*, with the defect stated as a defect and no repair applied:

- **`run_counts(isa_meas_list, shots, seed, sim)`** — `twin.py:54-63`. Record: per-circuit seeds are `seed + k`; on `AerSimulator.from_backend`, memories at seed *s* shifted by one equal memories at seed *s+1* across all 1,023 overlapping entries at 1,024 shots (measured, both production and compact paths); therefore **repeats are not statistically independent and the returned dictionaries must not be treated as independent draws**. Record the second defect separately: `sim.set_options(seed_simulator=...)` **mutates caller-owned state** — measured going 101 → 500 and persisting after return. Record the third: every circuit is re-transpiled inside the loop with a fixed `seed_transpiler`. Mark invariant `repeats are independent` as **VIOLATED**, cite `seed-diagnosis.json` and `equal-seed-control.json`, and mark the repair `PROPOSED, NOT IMPLEMENTED — blocked on Fable`.
- **`channel_weights(kept)`** and **`channel_closure_residual(kept)`** — `twin.py:105-143`. State the closure identity, and state that it is **basis-dependent, not structural**: `P_surv` and `P_other` both imply Σn = 4 and `P_BBbar` is caught by the |q| = 2 clause, but `P_meson` (all |q_v| = 1) admits Σq ∈ {0, ±2, ±4}, so a meson with Σq ≠ 0 enters the LHS and is excluded from the RHS and would produce a nonzero residual. Record that exhaustive enumeration of all 82 physical codes found **no such code** (`oracle-diagnostics.json`), so the identity holds on the present basis and **no channel-definition change is warranted** — and record that extending the basis (j_max = 1) reintroduces the hazard silently. This paragraph is the whole point of the document; do not compress it.
- **`channel_closure_residual` invalid-key behaviour** — both sides skip `l12.decode(...) is None`, so a rejected code with nonzero weight provably contributes zero residual (measured: code 1, weight 0.25, residual 0.0). Mark R9's demand for a nonzero residual from such an input **UNSATISFIABLE AS WRITTEN**, awaiting a ruling. Do not invent a contract to close it.
- **`physical_yield(counts, physical_keys)`** vs **`postselect(counts)`** — `twin.py:152-155` vs `:66-69`. Record the inconsistent empty-input contract: `physical_yield({}, set())` raises `ZeroDivisionError`; `postselect({})` returns `({}, 0.0)`. Mark `UNENFORCED`.
- **`observables`, `matched_subtraction`, `bootstrap`, `postselect`, `twin_backend`, `add_measurements`** — full entries. For `bootstrap`, state explicitly that its two-sigma is a bootstrap over the elements of `counts_list` and is therefore **only** an uncertainty if those elements are independent, which R13's entry above records they are not.
